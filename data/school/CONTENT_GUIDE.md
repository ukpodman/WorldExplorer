# School Learning content guide: adding and correcting lessons and questions

School Learning is data-driven. The interface (`ui/school.py`) and the engine (`core/school.py`) read the files below, so a new
lesson, question or subject needs **no interface code**.

```
data/school/
  subjects.json                     school → subjects (status "available" or "planned"; "engine": "interactive"), class levels
  geography/
    curriculum.json                 curriculum sections → topics (class level, objectives); "lesson": true marks a full lesson
    lessons/<lesson-id>.json        one file per lesson, including its question bank
    figures/<name>.svg              diagrams (generated by tools/build_school_figures.py)
    CURRICULUM_ALIGNMENT.md         curriculum report
    SOURCES.md                      educational references
    TEACHER_REVIEW_CHECKLIST.md     checklist for a qualified teacher
  nigerian-history/                 interactive subject (Primary 1–6, JSS 1–3)
    curriculum.json                 classes → terms → topics (verification, sources) → lesson ids
    lessons/<lesson-id>.json        one interactive lesson per file (parts A–K, activities, knowledge check)
    figures/<name>.svg              maps and drawings (generated by tools/build_history_figures.py)
    SOURCES.md                      curriculum and lesson sources, verification status
  citizenship-heritage/             interactive subject (SSS 1–3), same layout
```

## Structure

School (Nigerian secondary) → **subject** (`subjects.json`) → **class level** (SSS 1–3; JSS later) → **curriculum topic**
(`curriculum.json`) → **lesson** (`lessons/*.json`) → **practice** (the lesson's `practice` bank) → **progress** (per student and lesson).

## Lesson file (required keys)

| Key | Meaning |
|---|---|
| `id` | stable lesson id (lowercase letters, digits, hyphens). **Never change it**: saved progress is keyed by it. |
| `subject` | the subject id, e.g. `geography` |
| `number`, `title`, `short`, `minutes` | order, full title, short title, reading time |
| `level` | class levels, e.g. `["SSS 1", "SSS 2"]`; `level_note` explains the source |
| `version` | content version (integer). Increase it when you correct or extend the lesson. |
| `review_status` | `pending` until a qualified teacher has reviewed it (the app shows "Educational review pending") |
| `syllabus`, `objectives`, `intro` | where it fits, learning objectives, introduction |
| `sections` | `[{id, title, blocks}]`; each section is a page. **Section ids are stable**: students' reading positions follow them. |
| `definitions` | `[[term, meaning], …]` glossary |
| `worked` | `[{title, problem, steps, note?}]`. Use `note` to say when figures are illustrative. |
| `exam_tips`, `checks` (`{q, a}`), `summary`, `structured` (`{q, marks, model, points}`) | exam guidance, checks, revision summary, structured questions with model answers and marking guidance |
| `practice` | the question bank (at least 20 questions) |
| `references` | `[{title, url}]` |

Block types: `p` (paragraph), `h` (sub-heading), `list`, `cards` (`items: [{title, text, tone}]`, tone `teal|gold|ok|warn`),
`table` (`head`, `rows`), `figure` (`src`, `caption`, `credit`, where credit is required), `photo` (`src: "country:<ISO3>"`, which uses only
the app's licensed photos from `data/photos.json`) and `note`. Text may use `**bold**`.

## Practice question (required keys)

```json
{"id": "cl13", "subject": "geography", "topic": "ng-climate", "section": "weather", "difficulty": "easy",
 "q": "Which instrument is used to measure relative humidity?",
 "options": ["Hygrometer", "Barometer", "Anemometer", "Rain gauge"], "answer": 0,
 "explanation": "A hygrometer (wet-and-dry bulb thermometer) measures relative humidity. …"}
```

* `id` is unique across **all** lessons and never reused. The app remembers recently asked ids.
* `topic` is the lesson id. `section` is the id of the lesson section that teaches the answer: "Areas to revise" and "Revise" link to it.
* There are exactly four different options. `answer` is the index of the correct one. The app shuffles option order, so you can list the answer anywhere.
* `difficulty`: `easy`, `medium` or `hard`.
* Write original questions. Do not copy past-paper questions or textbook text.

## Correcting content without losing students' progress

1. Edit the lesson. Keep the lesson id, section ids and question ids.
2. To remove a question, delete it, but never reuse its id. To change a question's meaning, give it a new id.
3. Increase `version` by 1. Students who read the old version keep their completion, scores and position. Their position follows the section id.
   Their lesson card shows "Updated since you read it".
4. Run the checks: `python -m unittest tests.test_school`. `core.school.validate_lesson` fails loudly on missing keys, duplicate ids,
   bad options, unknown sections or figures without credits.

## Adding a subject

1. In `subjects.json`, set the subject's `status` to `available` and add `curriculum` (path), `levels` and `keywords`.
   Add `"engine": "interactive"` to use the interactive lesson format below instead of the Geography format.
2. Create `<subject>/curriculum.json` and `<subject>/lessons/*.json`.
3. Keep subjects that have no verified content as `planned`. They show "Coming soon" and have no buttons.

## Progress rules (the same as on the dashboard)

* **Not started:** no record. **In progress:** opened, not marked complete.
* **Completed:** marked complete after reaching the last page. A practice score never removes it.
* **Needs revision:** the student's revision list, or a best practice score below 6/10. It is shown alongside the reading status.
* **Read %** = (furthest page + 1) ÷ pages. **Average practice score** = mean of each practised lesson's best score.
* **Questions attempted** = all questions answered in finished rounds.
* Practice rounds take 10 questions from the bank. Questions from the student's last 20 are reused only when the bank runs out.

## Interactive subjects (Nigerian History; Citizenship and Heritage Studies)

Engine: `core/lessons.py` (curriculum, lessons, validation, pages, progress helpers) and `core/assess.py` (question types and
marking). Screens: `ui/school_interactive.py`. Progress uses the same records, account table and device cookie as Geography, so
**no database change** is needed for new lessons.

### Curriculum file

```json
{"subject": "nigerian-history", "version": 1, "note": "…", "sources": [{"id", "title", "url", "kind", "note"}],
 "classes": [{"id": "jss-1", "title": "JSS 1", "stage": "secondary", "note": "…",
              "terms": [{"id": "first", "title": "First Term",
                         "topics": [{"id": "jss1-sources-of-history", "title": "…", "verification": "scheme",
                                     "sources": ["sow-jss"], "lessons": ["jss1-sources-of-history"]}]}]}]}
```

* Term ids: `first`, `second`, `third`, or `unassigned` (shown as "Term not confirmed") when sources do not agree on terms.
* `verification` of every topic: `official` (checked against the official NERDC document), `scheme` (listed in published schemes of
  work that say they follow the NERDC curriculum, not yet checked against the official document) or `enrichment` (World Explorer
  material outside the prescribed curriculum). **Never mark a topic `official` without checking the NERDC document itself.**
* A lesson is attached by listing its id under one or more topics; the app shows it once and says "Covered in the lesson … above"
  under the other topics. A topic without a lesson file shows "Lesson not written yet".
* A class with no checked topics keeps empty terms and a `note` (as SSS 2 and SSS 3 of Citizenship and Heritage Studies do).

### Lesson file (`"format": "interactive"`)

| Part | Key | Notes |
|---|---|---|
| A | `introduction`, `why` | paragraphs; why the topic matters |
| B | `objectives` | |
| C | `background` | blocks; required for JSS and SSS lessons |
| D | `sections` | `[{id, title, blocks}]`, one page each; ids are stable |
| E | `key_figures` | `[{name, kind (person/place/event/institution/object), text, when?, approx?, basis?, src?}]` |
| F | `cause_effect` | `[{cause, effect, significance}]`; required for JSS and SSS lessons |
| G | `activities` | at least two (below) |
| H | `key_terms` | `[[term, meaning], …]` |
| I | `summary` | |
| J | `assessment` | at least 6 questions (primary) or 8 (secondary), not only multiple choice and true/false |
| K | `further` | `[{title, why}]` and `sources` `[{id, title, url (https), kind}]` |

Also: `id`, `subject`, `class` (as in the curriculum), `term`, `topic`, `stage` (`primary`/`secondary`), `number`, `title`, `short`,
`minutes`, `version`, `review_status` and `curriculum` `{verification, note, sources}`.

* `review_status`: `draft` → `reviewed` → `published`. Only `reviewed` and `published` lessons are presented as finished; drafts
  show "Educational review pending" and "Draft". Change it only after a qualified teacher has reviewed the lesson.
* Block types: `p`, `h`, `list`, `cards`, `table`, `figure` (`figure`: the SVG name, `caption`, `credit`), `note` and `quote_source`
  (`kind`: oral/archaeological/written/art/interpretation, `text`, `provenance`).
* Any block or item may carry `basis` (`fact`, `tradition`, `interpretation`, `disputed`, `approximate`) and `src` (source ids). The
  app shows them as labels and numbered references, so students can tell documented facts from traditions and interpretations.

### Activities

| `type` | Keys | Used for |
|---|---|---|
| `explorer` | `items` [{id, title, subtitle?, facts? [[label, value]], text}], `figure?` | sites, kingdoms, heritage items |
| `timeline` | `events` [{title, when, sort, approx, background}] in chronological order | Timeline Explorer (exact vs approximate) |
| `investigation` | `sources` [{kind, title, text, provenance, basis?}] (≥3), `questions` (≥2) | Historical Investigation |
| `story` | `chapters` [{title, text, inspect? [{label, text}], question}] (≥3), `note` | Interactive Stories |
| `practice` | `questions` | matching, ordering, civic scenarios, rights and responsibilities |
| `diagram` | `nodes` [{id, title, text, links}] (≥3), `questions?` | Government Institution Explorer |

Kingdom and site maps show **modern Nigeria for reference only**; never draw modern borders as historical boundaries. Stories
must not invent dialogue or quotations; their `note` says what is documented.

### Question types (`core/assess.py`)

`mcq`, `map`, `image` (`q`, `options` [{text, why}], `answer`; `figure` for map/image, `alt` for image) · `truefalse`
(`statement`, `answer`, `explain`) · `fill` (`text` with `___`, `answers`, `explain`) · `match` (`q`, `pairs`, `explain`) · `order`
(`q`, `items` in the right order, `explain`) · `scenario` (`situation`, `options` [{text, verdict best/acceptable/poor, why}],
`explain`) · `short` (`prompt`, `model`, `points`): written answers are **self-checked against the model answer, never marked
automatically and never counted** in scores. Every option of a choice question has its own `why`, shown after answering.

### Knowledge-check scores

Recorded in the existing fields: `best`/`last` = marked score scaled to 10, `attempts`, `answered`/`correct` = marked questions only.
A best score below 6/10 adds "Needs revision"; it never removes completion.

### Checks

`python -m unittest tests.test_school_interactive` validates every curriculum and lesson file (`core.lessons.validate_lesson`) and
exercises the screens.
